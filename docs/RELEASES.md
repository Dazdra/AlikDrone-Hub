# Выпуск публичного релиза

Публичный APK должен собираться только GitHub Actions из тега вида `vX.Y.Z-beta`. Локально собранный APK нельзя вручную подменять в Release: это нарушает связь между исходниками, подписью и опубликованным бинарным файлом.

## Подпись

Релизный ключ хранится вне репозитория и продублирован в зашифрованных GitHub Actions Secrets:

- `SIGNING_KEYSTORE_BASE64`;
- `SIGNING_STORE_PASSWORD`;
- `SIGNING_KEY_ALIAS`;
- `SIGNING_KEY_PASSWORD`.

Значения секретов нельзя выводить в логи, добавлять в файлы репозитория или передавать через issue/PR. Потеря постоянного ключа лишит пользователей возможности устанавливать обновления поверх текущей версии, поэтому владелец проекта обязан хранить автономную резервную копию.

SHA-256 сертификата публичного ключа:

```text
80:A5:29:FB:8D:53:63:02:B7:6C:27:2B:DF:99:01:EE:12:86:20:84:5E:0A:A1:2A:B4:9B:71:6A:E9:14:BB:9E
```

## Порядок

1. Обновить `versionCode`, `versionName`, `CHANGELOG.md` и release notes.
2. Добиться зелёного CI в `main`.
3. Создать аннотированный тег `vX.Y.Z-beta` на проверенном коммите и отправить его в GitHub.
4. Дождаться workflow `Release beta`.
5. Проверить APK, `SHA256SUMS.txt`, точный source ZIP и provenance attestation.
6. Установить опубликованный APK на реальный пульт перед анонсом широкой аудитории.

Workflow сам тестирует, собирает, подписывает и публикует релиз. Ручная замена APK после завершения workflow запрещена.
